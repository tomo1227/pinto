# Pinto for iPhone

iOS 17 以上の iPhone 向けの SwiftUI + UIKit アプリです。サーバー・外部 DB・追加パッケージは必要ありません。

利用者向けの操作手順は [ユーザーマニュアル](./USER_GUIDE.md) を参照してください。アプリ内では課題一覧の右上の「？」から、通信なしで閲覧できます。

お問い合わせは [Pinto サポート](https://tomo1227.github.io/pinto/)、データの取り扱いは [プライバシーポリシー](https://tomo1227.github.io/pinto/privacy.html) をご覧ください。

アプリに関する [お知らせ](https://tomo1227.github.io/pinto/news.html) と [リリースノート](https://tomo1227.github.io/pinto/releases.html) は、それぞれ [news.html](./docs/news.html) と [releases.html](./docs/releases.html) の記事一覧の先頭に追加します。GitHub Pages は `main` ブランチの `/docs` から公開し、各ページのヘッダーは Jekyll の [共通テンプレート](./docs/_includes/site-header.html) を使用しています。

## Xcode で開く

1. Mac の Xcode 15 以降で [Pinto.xcodeproj](./Pinto.xcodeproj) を開きます。
2. `PintoApp.swift` を開き、右上の **Canvas** を表示して **Resume** を押すと、ライブラリ画面を確認できます。
3. Scheme を **Pinto** にし、iPhone の Simulator を選択します。
4. **Run（⌘R）** で起動します。
5. 実機の場合は Pinto ターゲットの **Signing & Capabilities** で自分の Team を選択します。必要に応じて Bundle Identifier（初期値 `com.pinto.local`）を変更してください。

このリポジトリには開発者の署名情報を含めていません。依存ライブラリのインストールやプロジェクト生成は不要です。

## 機能

- 写真・ファイル・カメラから課題を登録。名前、グレード、日本語タグ、説明を編集。作成者・ジム名は任意のテキストとして入力可能
- 課題一覧のグリッド／リスト切り替え、名前・グレード・タグなどのローカル検索。グレードやホールド・ムーブ・タイプを選んで絞り込み。長押しで選択し、複数の課題をまとめて削除
- ホールドの追加・選択・移動・サイズ変更、端末内の色解析による輪郭検出、楕円／円の切り替え
- 文字の追加・再編集・移動・サイズ変更、色、太さ、ゴシック／明朝／等幅、縁取り
- ホールドを順番にタップしてルートを作成。線の色・太さ・縁取り、数字の色・サイズ、表示切り替え
- Undo / Redo、「消去」ボタンの長押しによる編集の全リセット

## 編集操作

- **課題一覧**: グリッド・リストのどちらも課題を長押しすると選択できます。ほかの課題をタップして選択に追加し、右上のゴミ箱からまとめて削除できます。リスト表示では左スワイプからの1件削除も可能です。どちらも削除前に確認画面が表示されます
- **ホールド**: 空いている場所をタップして追加。既存のホールドや文字をタップして選択し、ドラッグして移動
- **文字**: 場所をタップして入力。入力中は背景を暗くし、文字色・フォント・B（太字）／I（斜体）・文字サイズ・枠線の色と太さをその場で変更できます。フォントは横並びの書体見本から選択し、文字サイズはスライダーで調整。入力後も編集パネルで変更可能。既存の文字をタップすると再編集。空文字や空白・改行だけで「完了」を押すと編集中の文字を削除します（Undo で復元可能）。新規入力の場合は何も追加せず閉じます
- **ルート**: ホールドを順番にタップして追加。登録済みのホールドを再タップすると、ホールド自体は残したままルートから削除します。もう一度タップすると末尾へ追加されます。追加・削除は Undo / Redo に対応します。「ルート」選択中の編集パネルで「ルートの数字サイズ」を 6〜60 の範囲で調整できます（初期値 13）。サイズは保存画像にも反映され、Undo / Redo に対応します。ルート線と数字をそれぞれ独立して表示／非表示にできます。非表示にしてもルートの順番は保持します
- **消去**: ホールド・文字をタップして削除。ホールドを削除するとルートからも外れます。右下の「消去」ボタンを0.6秒長押しし、確認画面で「全リセット」を選ぶとホールド・文字・ルートをすべて削除します。全リセットも Undo で取り消せます
- **画像を移動**: ドラッグで画像を移動、ピンチでズーム、画像表示エリアの右下のボタンで表示をリセット
- **戻る**: 未保存の編集データを即座に自動保存して課題一覧に戻ります。保存に失敗した場合はエラーを表示し、再試行・破棄・編集継続を選べます
- 選択中のホールドや文字を0.5秒長押しするとゴミ箱が表示されます。ゴミ箱へドラッグし、赤くなったところで離すと削除。ゴミ箱以外で離すと移動として確定し、削除も移動も Undo で取り消せます
- ホールドの選択枠の四隅と各辺にある、青い枠の四角いハンドルをドラッグしてサイズを変更。左右の点は幅、上下の点は高さ、角の点は両方を変更します。外側へドラッグすると拡大、内側へドラッグすると縮小し、中心位置は変わりません。円モードでは真円を維持します。文字は四隅のハンドルでサイズ変更できます。選択物の上でピンチすると縦横を同時に拡縮。「見た目」でもサイズや装飾を変更できます。ドラッグ1回を Undo / Redo で取り消し・やり直しできます

輪郭検出は写真の色の差を利用する方式で、AI や外部 API は使用しません。検出できない場合は通常の丸を配置します。

## 保存

アプリの Application Support 内の `Pinto/` に、元画像（向きを補正した `<UUID>.png`）と編集データ（`<UUID>.pinto` の JSON）を別々に保存します。自動保存では編集データだけをアトミックに更新します。旧形式の課題は一覧の読み込み時に移行し、元画像を保存できてから JSON を置き換えます。データベースは使いません。履歴には画像を含めず、直近 100 操作を画面表示中のみ保持します。

編集データは変更が 0.5 秒途切れると自動保存します。ホールド・文字・ルート・表示設定・課題の設定の変更と Undo / Redo が対象です。連続した操作中は保存をまとめ、一覧へ戻るときやアプリが非アクティブ／バックグラウンドになるときは待たずに保存します。文字の入力途中は確定せず、「完了」で反映した内容を保存します。

編集画面は通常、長辺が最大 2560 ピクセルのプレビューを表示します。ズームでプレビューの解像度を超えた場合は元画像を表示します。輪郭検出と書き出しには常に元画像を使います。

上部の保存ボタンは、ホールド・ルート・文字を合成した PNG 画像を写真ライブラリ（カメラロール）に追加します。自動保存では写真ライブラリへの追加は行いません。画像は元写真のピクセル数で保存し、選択枠や操作ボタンは含めません。ルート線と数字の表示設定も反映します。初回は写真への追加許可を求めます。許可されなかった場合や画像の保存に失敗した場合はエラーを表示しますが、端末内の編集データは保持します。保存中は連打を防止し、完了すると画面に通知します。

保存失敗は画面に表示し、編集中のデータを残します。読み込めないファイルはエラーを表示し、削除・上書きしません。

保存ボタンの隣の共有ボタンで、ホールド・ルート・文字を合成した画像を iOS の共有シートへ渡せます。AirDrop やメッセージなど、端末で利用可能な共有先を選べます。元写真のピクセル数とルートの表示・数字サイズ設定を反映し、選択枠や操作ボタンは含めません。共有するだけなら写真ライブラリへの追加許可は不要です。

編集データのインポート／エクスポートには対応していません。アプリ削除・端末紛失に備え、必要に応じて端末のバックアップを利用してください。

## 検証

Xcode の **Product → Test（⌘U）** で `PintoTests` を実行できます。保存・再読み込み・破損データ、ルートの整合性、Undo / Redo、ジェスチャーの履歴、輪郭検出、PNG の寸法と線のスケールなどをテストします。
自動保存テストでは待機を制御し、実時間で 0.5 秒待たずにキャンセルや即時保存との順序を検証します。

ローカルの `make test` はビルドとテストを続けて実行します。CI ではシミュレータの起動を先に始め、`make build-ios-tests` でビルドしてから、同じシミュレータが起動したことを確認して `make test-ios-without-building` を実行します。CI ログではビルド、起動待ち、テスト実行を別々に確認できます。

リポジトリルートからのビルド例:

```sh
xcodebuild -project Pinto.xcodeproj -scheme Pinto \
  -destination 'generic/platform=iOS Simulator' CODE_SIGNING_ALLOWED=NO build

# 利用可能な Simulator を確認し、次のコマンドの端末名を置き換える
xcodebuild -project Pinto.xcodeproj -scheme Pinto -showdestinations
xcodebuild -project Pinto.xcodeproj -scheme Pinto \
  -destination 'platform=iOS Simulator,name=iPhone 16' test
```

### Copilot で SwiftUI をレビューする

`make apm_ci` で Copilot 用のスキルを復元できます。Copilot Chat では、たとえば「`swiftui-performance-audit` を使って、写真を取り込んだ後に編集画面の描画が重くなる原因を調べて。コードはまだ変更しないで」と依頼できます。コードだけで原因を絞れない場合は、Instruments で計測する手順も提案します。

### Copilot で Swift Testing をレビューする

Copilot Chat で「`swift-testing-pro` を使って、Pinto のテストをレビューして」と依頼できます。このスキルも `make apm_ci` で復元できます。

ビューの構成を整理したいときは、「`swiftui-view-refactor` を使って、編集画面をどうサブビューに分割するか提案して。挙動は変えず、コードはまだ変更しないで」と依頼できます。

### Debug 実行時のメモリ確認（目安: 300 MB）

1. Xcode の **Product → Scheme → Edit Scheme → Run → Arguments** を開き、**Arguments Passed On Launch** に `-PintoMemoryCheck` を追加して有効にします。
2. Simulator または実機で Debug の Pinto を起動します。画面右上の `RAM` は Pinto プロセスの現在のメモリ使用量（physical footprint）、`Peak` は OS が記録した起動後の最大値です。単位は `1 MB = 1,000,000 bytes` です。
3. 大きな写真を取り込み、編集画面を開いてホールドの輪郭検出、画像保存・共有、一覧への復帰を試します。何度か繰り返し、`Peak` が 300 MB 以下か確認します。画面がシートで隠れていても、閉じたあとにピークを確認できます。操作ごとに比較する場合は、アプリを完全に終了してから起動し直します。

300 MB を超えると表示が赤くなり、最初の超過を `MemoryCheck` カテゴリのログに出します。これはビルドや Simulator 全体の使用量ではなく、アプリ単体の計測です。Simulator と実機の値は異なるため、最終判断は実機で行ってください。このチェックは使用量を制限せず、引数なしの起動や Release ビルドには表示されません。
